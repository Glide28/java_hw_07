Тема: «Работа с базой данных. Часть 2».

Приложение переведено с JDBC на Spring Data JPA и Hibernate. Для локального запуска используется встроенная база H2, а схема создаётся автоматически через `spring.jpa.hibernate.ddl-auto=create-drop`.

## Реализовано

- сущности `User` и `Message` со связью `Many-to-One` (`Message → User`);
- репозитории `JpaRepository` без ручной JDBC-логики;
- демонстрационный запрос с проблемой N+1;
- оптимизированный запрос без `@Query`: derived-метод Spring Data JPA и `@EntityGraph` загружают сообщения и авторов одним SQL-запросом;
- решение проблемы `LazyInitializationException` через DTO `MessageResponse`;
- автоматическая генерация схемы Hibernate;
- интеграционные тесты REST API и слоя данных.

## API

- `GET /api/messages/nplus1` — учебная демонстрация N+1;
- `GET /api/messages/optimized` — оптимизированная загрузка сообщений с авторами;
- `GET /api/messages/fail/{id}` — безопасная выдача сообщения через DTO;
- `POST /api/messages` — создание сообщения, например:

```json
{
  "content": "Новое сообщение",
  "username": "Arseniy"
}
```

## Сборка и тесты

```powershell
.\gradlew.bat clean test
```

## Запуск

```powershell
.\gradlew.bat bootRun
```

После запуска приложение доступно по адресу `http://localhost:8080/api`.

## Сложность операций

- сохранение сообщения — в среднем `O(1)` плюс поиск пользователя по уникальному индексу `O(log n)`;
- чтение последних 30 сообщений — ограничено константой `30`, то есть `O(1)` относительно общего числа записей;
- оптимизированный вариант выполняет один SQL-запрос вместо `1 + N` запросов.
